# 部分失败时保留旧条目并以非零退出码结束

单个 Pin 更新失败（上游限流、网络错误、Derived Hash 构建失败）不应废弃整轮结果，因为 Derived Hash 的计算成本高昂。失败的 Pin 在 Pins File 中保持上一轮的完整条目不变——不删除、不标记为失败——因此 Pins File 始终可构建。成功的 Pin 正常写入。退出码用于区分「全部成功」与「有失败但已写入」。

## Considered Options

- 整体失败且不写入：单个上游限流即废弃整轮更新，nvfetcher 正因此需要 `--keep-going`。若接入自动开 PR 的流水线，此选项反而更合理，因为部分更新的 PR 比失败的 CI 更难处理。
- 尽力而为且退出码 0：CI 会静默通过，用户误认为更新已完成。

## Consequences

用户可能忽略退出码而把部分更新的 Pins File 当作完整更新。缓解措施：stderr 摘要需醒目列出失败项，且 `status` 子命令能列出上次更新失败的 Pin。

本决策假定工具以手动运行为主、CI 运行为次。若后续主用法转为自动开 PR，应重新审视此 ADR。
