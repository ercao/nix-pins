# Pin 拥有多个具名 Source

一个 Pin 拥有一个 Checker、一个 Version 与多个具名 Source；每个 Source 独立拥有 Fetcher、源码 Hash 与 Package 集合。公共 DSL 使用 `pin.mk { checker; sources; }`，不新增与领域术语冲突的 `pin.group`。Source 参数与原有单 Source 顶层参数相同，但不包含 `checker`；存在 `sources` 时只使用其中的声明并忽略顶层 `fetcher`、`packages`、`patches` 与 `postPatch`，不存在时将原有单 Source 形式规范化为 `sources.default`。Pin 是不可拆分且原子提交的 Selection 与 Update 单元，Source 不能单独更新；Checker 只执行一次，任一 Source 的 Fetcher 或 Hash 失败时，全部 Source 保留上一轮可用结果，并只记录一条包含实际失败 Source 名的 Pin Failure。所有选中 Pin 的 Source 与 Derived Hash 任务使用现有 `NIX_PINS_HASH_JOBS` 池并行计算，不增加 Source 专用并发配置；并发结果仍按 Pin 聚合后原子提交。Pins File 升级为 schema v2，在 Pin 下嵌套 Sources 并只存储一次 Version；Reader 严格保留 `Pin → Sources → Source` 层级，不为单 Source 提升 `src`、Hash、Derived Hash 或 Package 属性。交互式进度使用 Pin、Source、Package 三层，唯一 `default` Source 或 Package 可以折叠。本次设计不保留 Pins File schema v1 兼容性。
